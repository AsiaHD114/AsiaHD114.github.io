# ⚠️ 必须是 true，不能删。
# 站点根目录的 scripts/comments-default-off.js 按这个键决定是否显示评论区：
#   有 comments_on: true  → 显示
#   没有（或其它值）      → 不显示
# 全站只有这一页写了它，所以这里是唯一的评论区。
#
# ⚠️ 别写成 comments: true —— Hexo 给 comments 的默认值本来就是 true，
#    写成那样起不到开关作用（这个坑实测踩过，日志可证）。
comments_on: true
#
# ===========================================================================
# 评论字数上限为什么是 500 —— 决定：**保留 500，不往上调**
# ---------------------------------------------------------------------------
# 这是一个前后端计数口径不一致的问题，不是配置写错：
#
#   前端计数器   按「输入框里的纯文本字数」算
#   后端校验     按「Markdown 转成 HTML 之后的字符串长度」算
#                —— @twikoojs/common/dist/index.cjs 第 856 行：
#                     if (limitLength && comment.comment.length > limitLength)
#                       throw new Error("评论内容过长")
#
# 两者的差值就是标签本身：单段纯文本转出来是 <p>…</p> 加一个换行，
# 多出 8 个字符；分段、粗体、表情、图片会更多。
#
# 实测：输入框显示 499/500（前端认为没超）→ 后端收到 507（超了）→ 报「评论内容过长」
#
# ⇒ 保留 LIMIT_LENGTH=500 时，实际能写约 492 个纯文本字。
#    这是保留 500 的代价，已确认接受。
#    若以后想放宽：后台把 LIMIT_LENGTH 调大即可（600 ≈ 592 字），
#    前端计数器会自动跟着变，因为它的上限读的就是这个值。
#
# ⚠️ 这个值存在 Twikoo 后台（MongoDB），不在本仓库里，所以这里只能记录结论。
#    改法：评论区齿轮 → 登录 → 设置 → LIMIT_LENGTH。
# ===========================================================================
#

#     HTML 源码（虽然不可见），front-matter 的 YAML 注释则完全不会进产物。
