等保 2.0 是绕不过去的一件事。只要系统面向公众提供服务、或者归在关键信息基础设施里，早晚会有人来问你「几级」「备案了吗」「测评报告呢」。

这篇把整条链路捋一遍：**定级 → 备案 → 建设整改 → 等级测评 → 监督检查**，附上每一步的实际产出和容易踩的坑。写给要自己动手推进的人，不是写给采购的。

## 先对齐几个基本概念

| 项目 | 内容 |
| --- | --- |
| 全称 | 网络安全等级保护（信息安全等级保护 2.0） |
| 核心标准 | GB/T 22239-2019《网络安全等级保护基本要求》 |
| 上位法 | 《网络安全法》《数据安全法》《个人信息保护法》 |
| 主管 | 公安部网络安全保卫局及各级网安部门 |
| 与 1.0 的关系 | 1.0 是 GB/T 22239-2008，2.0 是它的替代版本，2019 年发布、2020 年起全面施行 |

一句话概括 2.0 相对 1.0 的变化：**保护对象从「信息系统」扩到了「网络」，防护思路从「分区分域」升级成「一个中心、三重防护」。**

「一个中心」指安全管理中心，「三重防护」指安全通信网络、安全区域边界、安全计算环境。这个模型很重要，后面看测评项分布时会一直用到。

## 标准体系：先看清有哪几本

实际干活会用到的国标大致是这几本，分工不同，别混：

| 标准号 | 名称 | 干什么用 |
| --- | --- | --- |
| GB/T 22239-2019 | 网络安全等级保护基本要求 | 到底要满足哪些要求，一切的核心 |
| GB/T 22240-2020 | 网络安全等级保护定级指南 | 怎么定级 |
| GB/T 28448-2019 | 网络安全等级保护测评要求 | 测评时逐条判定的依据 |
| GB/T 28449-2018 | 网络安全等级保护测评过程指南 | 测评机构怎么开展作业 |
| GB/T 25058-2019 | 网络安全等级保护实施指南 | 从零开始怎么落地 |
| GB/T 25070-2019 | 网络安全等级保护安全设计技术要求 | 技术方案怎么设计 |
| GB/T 36627-2018 | 网络安全等级保护测试评估技术指南 | 评估用的技术手段 |
| GB/T 32919-2016 | 工业控制系统安全控制应用指南 | 工控场景专项 |

标准号和年份请以[国家标准全文公开系统](https://openstd.samr.gov.cn/)的现行版本为准，标准会修订，我这篇记录的是我经手时的版本。

## 一、定级：一切的起点，也是最容易出问题的一步

定级由**运营使用单位自己定**，不是测评机构替你定。定级方法在 GB/T 22240 里，核心是两个要素的组合：

1. **受侵害的客体** —— 系统被搞坏之后，受害的是谁？是公民/法人的合法权益，还是社会秩序和公共利益，还是国家安全？
2. **对客体的侵害程度** —— 一般损害、严重损害，还是特别严重损害？

客体和程度组合，落到一级到五级。五个级别有正式名称，写定级报告时会用到：

| 级别 | 名称 | 大致对应 |
| --- | --- | --- |
| 第一级 | 自主保护级 | 普通官网、内部 OA 一类，损害只到本单位或用户 |
| 第二级 | 指导保护级 | 一般企业核心业务系统、地市级政务系统 |
| 第三级 | 监督保护级 | 省级以上政务、金融核心、三甲医院 HIS 这类 |
| 第四级 | 强制保护级 | 国家重要基础设施，电网、核电这一类 |
| 第五级 | 专控保护级 | 极少数，实务中基本见不到 |

实务里 **二级和三级占绝大多数**，四级以上很少。

### 定级阶段要产出什么

- 定级报告（把两个要素的推理过程写清楚，不能只写结论）
- 专家评审意见（一般要求 5 名以上相关领域专家）
- 上级主管部门的审批意见（有上级单位的话）

### 最常见的坑：定级偏低

见过太多单位为了省事往低了定。风险很实在：一旦遇到检查或审计被要求提级，前面按低级别建的设备、写的制度、做的配置**全部要返工**，而且提级往往发生在系统已经上线跑了一年之后，改动成本比一开始就定对高得多。

反过来定高了也不划算，三级比二级多出一大截测评项和建设成本。**定级的正确姿势是老老实实按两个要素推，而不是先想好要几级再倒推理由。**

## 二、备案：去属地公安网安部门

定级完成后到属地公安网安部门备案。材料大体是这几样：

- 定级报告
- 专家评审意见
- 系统拓扑图
- 资产清单（设备、系统、数据）
- 备案表（按当地网安给的模板填）

受理后一般 **10 个工作日左右**出结果，拿到备案证明。各地要求细节会有差异，第一次办建议先打电话问清楚，别按上一次的经验直接去。

## 三、建设整改：把要求对上现状

这一步是把 GB/T 22239-2019 里对应等级的要求，和自己系统的现状逐条比对，然后补差距。

### 十个安全类，五技术 + 五管理

| 分类 | 安全类 |
| --- | --- |
| 技术 | 安全物理环境、安全通信网络、安全区域边界、安全计算环境、安全管理中心 |
| 管理 | 安全管理制度、安全管理机构、安全管理人员、安全建设管理、安全运维管理 |

每个安全类下面才是具体的测评项。规模上，业内常引用的口径是**三级通用要求约 211 项、二级约 135 项**，这个数字不含云计算、移动互联、物联网、工业控制这些场景的**扩展要求**——如果你的系统跑在云上或者有 App、有 IoT 设备，还要把对应扩展要求叠上去，项目数会更多。

### 整改怎么排优先级

别按标准的章节顺序改，按这个顺序：

1. **能一票否决的先改** —— 高风险项、关键项不符合，可能直接导致测评结论不通过，性价比最高。
2. **技术类里投入产出比高的先改** —— 关端口、改默认口令、开日志审计、上 HTTPS，这些改动小但覆盖的测评项不少。
3. **需要采购的排中期** —— WAF、IPS、堡垒机、日志审计平台、数据库审计这类，走采购流程要时间。
4. **管理类制度最后补齐但别漏** —— 很多单位「重技术轻管理」，制度文件不全，测评时白丢分，而补制度几乎不花钱，只是要有人写、有人签、有人执行。

## 四、等级测评：谁来测、怎么测、结论怎么判

### 谁来测

必须由**公安部网络安全等级保护测评机构推荐目录**内的机构来做。这是硬要求，目录外的机构出的报告在监管那里不认。

### 怎么测

测评机构的作业方式就四件事：

- **访谈** —— 找运维、安全、开发的人聊，问流程怎么走的
- **查看** —— 翻制度文件、配置截图、日志记录
- **测试** —— 上技术手段验证，漏洞扫描、配置核查、必要时的渗透测试
- **分析** —— 对照要求逐条给出判定

### 单项判定与整体结论

单个测评项的判定结果是几种：符合、部分符合、不符合、不适用。**「不适用」很重要**——比如纯内网系统没有互联网出口，相关项可以判不适用并从分母里剔除，不是所有项都算分。

整体结论按综合得分分档，常见口径是：

| 档位 | 综合得分 |
| --- | --- |
| 优 | ≥ 90 |
| 良 | 80 ~ 90 |
| 中 | 70 ~ 80 |
| 差 | < 70 |

注意得分不是唯一依据：**如果存在高风险项，即使总分够也可能判不通过。** 具体判定规则以 GB/T 28448-2019 原文和测评机构的判定为准，别只盯分数。

### 周期和产出

- 现场测评通常 7~15 天，规模大的更久
- 报告撰写 5~7 天
- 整个测评阶段合计 **15~30 天**
- 产出：《等级测评报告》+ 结论 + 整改建议清单

拿到「基本符合」也别急着松口气——整改建议清单里那些没改完的项，下一次测评还会回来找你。

## 五、监督检查与持续合规

网安部门会做例行检查和专项检查，重点看三件事：**上一轮整改落实了没有、变更管理有没有记录、出安全事件能不能应急响应。**

### 复测周期

- **三级及以上：每年至少 1 次**
- **二级：一般每 2 年 1 次**

另外，系统发生**重大变更**——架构改造、迁移上云、新增重要模块——之后要重新评估，必要时变更备案并重新测评。很多人漏掉这一条，等检查时才发现自己的架构早就和备案时不是一回事了。

## 六、资料准备清单

按这四类准备，测评前一周翻一遍，比临时找强得多。

**技术资料**

- 系统拓扑图，要能看出网络分区和安全设备位置
- 资产清单：服务器、存储、网络设备、安全设备
- 软件清单：操作系统、中间件、数据库、应用及版本
- 数据流图：敏感数据从哪来、到哪去、存哪
- 接口清单：和外部系统的对接关系

**管理制度**

- 信息安全总体方针和策略
- 人员安全管理（入职、离职、考核）
- 访问控制（账号、权限、口令策略）
- 变更管理、应急响应、备份恢复
- 第三方接入与外包人员管理

**日志与记录**

- 系统操作日志，**留存不少于 6 个月**
- 安全设备告警日志
- 应急演练记录
- 变更审批记录、漏洞修复记录

**人员安全**

- 安全管理岗位职责
- 关键岗位人员审查记录
- 安全培训记录
- 保密协议签订情况

## 七、最常见的六个整改痛点

**① 边界防护形同虚设**
互联网出口没有 WAF、没有入侵防御、没有流量审计，访问控制策略粗放。这是被点名最多的一类。

**② 主机加固没做**
非必要端口开着、默认口令没改、没装防病毒、日志审计没开。这几项改动量极小，但覆盖的测评项不少，属于「不做纯亏」。

**③ 应用层漏洞**
SQL 注入、XSS、弱口令、敏感信息泄露。建议在建整改阶段同步做一遍 OWASP Top 10 的自查或第三方扫描，别等测评现场被扫出来。

**④ 数据没加密**
敏感数据落库明文、只跑 HTTP、密钥管理随意。传输加密基本已经是底线要求了。

**⑤ 备份不可用**
有备份策略但没有异地、更没有做过恢复演练。「备份成功」和「能恢复」是两件事，测评时会问演练记录。

**⑥ 制度文件缺失**
技术做得不错，制度一片空白。这类失分最冤——补文件几乎不花钱，只是需要有人认真写、真正执行，而不是测评前赶一份模板。

## 八、几个常见误区

**「等保就是买设备」** —— 设备只是技术类里的一部分，管理类的五个安全类一分钱不用花，但照样占分。

**「测评过了就没事了」** —— 三级每年都要测，这是一套持续机制，不是一次性考试。

**「先上线再补合规」** —— 涉及重大变更后要重新评估甚至重新测评，先斩后奏往往意味着二次整改。

**「定级越低越省事」** —— 被要求提级时，返工成本远高于一开始就定对。

## 九、排期建议

把整条链路串起来，从零开始的时间预算是 **3~6 个月**：

| 阶段 | 大致耗时 |
| --- | --- |
| 定级 + 专家评审 | 2~4 周 |
| 公安备案 | 1~2 周（含材料准备） |
| 建设整改 | 1~3 个月，取决于采购量 |
| 等级测评 | 2~4 周 |
| 整改复测（如需） | 2~4 周 |

想卡上线时间的，从「建设整改」倒推，不要从测评开始倒推——测评是可预期的，采购和整改不是。

## 十、我自己的几点看法

前面九节是「怎么做」。这一节是「我怎么看」，带主观判断，不同意很正常。

### 合规动作和真实安全收益，得分开算

我喜欢把整改项分成三类，排期时按这个分：

- **真收益** —— 关非必要端口、改默认口令、最小权限、开日志审计、及时打补丁、传输加密。这些不管有没有等保都该做，而且几乎不花钱，只花时间。**能立刻做的一律先做。**
- **以合规为主** —— 上网行为管理、部分审计类设备、制度文件的格式要求。做了不亏，但别指望它把安全水位抬高多少。
- **两者兼有** —— 堡垒机、集中日志、双因素。前期是合规驱动，用起来之后确实能救命——**前提是真的在用**。

见过不少单位买齐了设备，堡垒机装上去只做登录跳板、命令审计没开，账号还是共享的。这种情况在测评里能过，在事故里等于没有。

### 等保看的是「有没有」，不太看「有没有效」

报告上写「已部署 WAF」和「WAF 的策略确实拦住了这波攻击」，完全是两件事，而测评基本只能验证前者。

所以我的定位是：**把等保当成基线，不要当成目标。** 过了等保说明没有明显短板、基本管理动作到位；但它不保证经得起有针对性、有耐心的攻击。真正检验这件事的是攻防演练和真实的事件响应，不是那张报告。

### 管理类最容易做成纸面工程

制度按模板抄一份，签名一填，测评也能过。但如果实际的账号开通还是「群里说一声就开」，那份制度的价值是**负的**——它给你一种「已经管住了」的错觉，比没有制度更糟，因为你不会再为这件事担心。

我判断一条制度有没有真正落地，只用一个问题：

> **这条制度如果明天开始不执行了，会有人发现吗？**

没人会发现，那它大概本来就没在起作用。这条判据我用了很多年，误判率很低。

### 把合规做成能重复执行的，而不是一年打一仗

三级每年测一次。如果每年都靠人肉翻配置、翻记录、临时补材料，这个成本会年复一年地付下去，而且每次都提心吊胆。

我的做法是分两条线落：

- **技术类**尽量变成**可自动核查的基线**——配置核查脚本、云平台的配置审计规则、CI 里跑一遍基线检查。目标是测评前导出一份报告，而不是打一场仗。
- **管理类**尽量变成**有固定节奏的动作**——季度账号权限复核、半年应急演练、变更必须留单、离职当天回收权限。节奏固定了，证据是自然攒出来的，不需要临时补。

### 一套动作，尽量对上多个标准

等保的十个安全类，和 ISO 27001 的控制域、CIS Benchmark 的条目，重合度其实很高。先把**资产、账号、日志、变更**这四件事按等保的口径理顺，再去对别的标准，大部分工作是复用的。

顺序反过来的话（先按某个国际标准做完再回来对等保），通常要重复劳动一遍——这是我踩过的坑。

### 如果只能挑一条做到位，我挑日志

十条安全类里，如果只允许我把一件事做到位，我选**日志**。理由是它一份投入解决三件事：

1. 测评要求里有，而且有明确的留存期要求
2. 出事要查，没有日志就只能靠猜
3. 被问起来要有证据，谁在什么时候改了什么，白纸黑字

更关键的是，日志是少数**今天开始做、明天就有收益**的控制项。太多单位是出了事才发现自己什么记录都没有——那种「想查但查不了」的感觉，比事故本身还难受。

## 小结

等保 2.0 这条链路本身不复杂：**定级要按要素推、备案要按属地办、整改要按优先级改、测评要找目录内机构、通过之后还要按周期复测。**

真正花时间的从来不是填表，而是把「一个中心、三重防护」这件事在自己系统里真正落实——而这部分工作，即使没有等保要求，也是该做的。
